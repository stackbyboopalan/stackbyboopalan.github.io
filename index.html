Security built into every layer

Financial data demands defence in depth. These are the controls I design and implement, from the first commit to production.

🔐

Identity & access

OAuth2/JWT with short-lived tokens, refresh rotation and role-based access on every API.

🔒

Encryption

TLS in transit; encrypted databases, backups and object storage at rest.

🗝️

Secrets management

No secrets in code. Keys live in a managed vault and are injected at runtime, with rotation.

🧱

Edge protection

WAF rules, rate limiting and request validation stop abuse before it reaches services.

🔎

Shift-left scanning

SAST, dependency and container image scans gate every merge in CI/CD.

📜

Audit & compliance

Immutable audit trails and centralized logs that support SEBI research-analyst obligations.

🧩

Network isolation

Private subnets, least-privilege IAM and scoped service accounts between workloads.

🤖

AI guardrails

Agents use read-only tools, scoped data access, prompt-injection filtering and disclaimer policies.

// secure payments

Payment gateways, integrated securely

I integrated Razorpay, PhonePe and PayU into RhoFi for subscription billing, behind one payment service. The product calls a single interface, and each gateway can be enabled, swapped or used as a fallback without changing the app.

Razorpay

Cards · UPI · netbanking · subscriptions
  • Orders created server-side; amount read from our DB
  • Checkout signature verified with HMAC-SHA256
  • Webhooks verified via X-Razorpay-Signature
  • Recurring subscriptions and refunds via API

PhonePe

UPI-first payment gateway
  • Server-to-server payment initiation
  • Signed requests with SHA-256 checksum
  • Callbacks verified before any state change
  • Final status confirmed via status-check API

PayU

Hosted checkout · cards · EMI
  • Request hash generated server-side with SHA-512
  • Reverse-hash check on every response
  • Verify-payment API used for reconciliation
  • Merchant salt kept only in the secrets vault
Create order

Server creates the order with an idempotency key. Price comes from the plan, never from the client.

Hosted checkout

Card and UPI details stay on the gateway, which keeps PCI-DSS scope minimal.

Verify

Signature or hash plus amount and currency checked server-side.

Webhook → Kafka

Verified events are processed idempotently, with retries and no duplicates.

Reconcile & activate

Status APIs confirm the payment, then the subscription is activated and audit-logged.

// now building

MCP-powered algo trading

My current build is an MCP (Model Context Protocol) server for algorithmic trading. It gives an AI agent typed, permissioned tools to read trade signals, validate entries and place orders through the broker API. Every order passes a risk gate that runs in code, outside the model.

In progress · details will be added as it ships

🧰 MCP tools the agent can call

get_signalsStrategy signals per instrument and timeframe
get_market_dataLive quotes, OHLC candles and indicators
validate_entryConfirms entry price, trend and volume before acting
check_riskPosition size, max loss and exposure limits
place_orderOrder with stop-loss and target via the broker API
get_positionsOpen positions, P&L and order status

🛡️ Safety built into the server

  • Read tools and order tools are separated, and order tools need explicit permission
  • Hard risk limits and a kill switch enforced server-side
  • Entries checked against multi-condition rules before any order
  • Paper-trading mode before live capital
  • Every signal, decision and order is audit-logged
  • Broker tokens kept in the vault, never exposed to the model
Signal intake

Strategy and market-data signals stream in, with indicators computed per instrument.

Agent via MCP

The AI agent reads signals and context through typed MCP tools.

Entry validation

Price, trend, volume and timeframe confirmation for a precise entry.

Risk gate

Size, max loss and exposure checked in code. The model cannot override it.

Place & track

Order sent with stop-loss and target via the broker API, then monitored and logged.
